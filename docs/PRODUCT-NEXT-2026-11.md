# 见闻 / 拙政观景：现在能做什么，以及下一步做什么

> 基于当前线上版本与仓库代码整理；建议部分由本地 Qwen 模型先出草案，再按现有架构和成本人工筛选、排序。

## 一、见闻（jianwen.xin）

### 现在能做什么

| 模块 | 能力 |
|---|---|
| 今日 | 每天 5 篇公开文章整理，卡片流、已读状态、今日理解进度 |
| 朗读 | 见闻 / 男声两种声音；每天一条连续音轨；锁屏/切后台连续播放；网页与 App 同一套连续音轨 |
| 阿烬 | 基于当日内容与经典文献的 AI 问答，支持来源、追问 |
| 经典文献 | 党章、团章、宣言、毛选、邓选等全文阅读器，章节进度保存在本机 |
| 发现 | 主题频道、经典书架、专题、最近更新、搜索 |
| 每周 | 每周视频（含章节、延伸阅读、来源）+ 登录后的个人周报长图 |
| 账号 | 手机号 + 短信验证码注册/登录/重置密码；收藏、历史、问问记录、关注主题云同步 |
| 多端 | 响应式网站 + Android App（WGT 热更新） |
| 数据 | 阅读活动采样、连续阅读、已读回写、阅读历史归档 |

### 建议（按优先级）

**P0｜先把“听”做稳（1–2 周）**

1. **Android 前台服务保活**
   现在锁屏后靠 JS 自动拉起，遇到 ROM 冻结进程仍会停。整包加原生前台服务 + 媒体通知，才是彻底方案；顺带把播放控制做到通知栏/锁屏。
   投入：中｜收益：直接决定“今日朗读”能不能日常用。

2. **断点续播 + 跨端进度**
   连续音轨记住“听到第几秒”，换设备/重装后从上次位置继续；网页与 App 共用同一进度。
   投入：小｜收益：长音频的必需体验。

3. **每日五篇闭环**
   读完 5 篇后的完成态、连续天数、断签提醒；把“今日理解进度”做成可分享的轻量卡片。
   投入：小｜收益：留存，比新增内容更划算。

**P1｜让内容更有用（1 个月）**

4. **阿烬回答带原文引用**
   每个结论后挂“依据段落”，点击跳到文章/经典原文对应位置，减少“AI 说的能信吗”的疑虑。
   投入：中｜收益：可信度与停留时长。

5. **离线缓存**
   今日 5 篇 + 当天连续音轨可一键缓存，地铁/飞机场景可用；缓存管理页可清理。
   投入：中｜收益：通勤场景刚需。

6. **经典文献笔记与高亮**
   划线、批注、按书导出 Markdown/PDF；和“阿烬”打通，提问时可引用自己的笔记。
   投入：中｜收益：把“读过的书”变成个人资产。

**P2｜增长与差异化（季度）**

7. **主题订阅与提醒**
   关注“就业/住房/医保”等主题，有新内容时站内信/推送；不做泛新闻推送，只做主题。
   投入：小｜收益：回访。

8. **周报分享图**
   现有周报长图加“可隐藏隐私数据”的分享版，适合小红书/朋友圈传播。
   投入：小｜收益：低成本获客。

9. **语音笔记**
   听完一段直接语音记想法，转文字挂到文章；可作为阿烬的上下文。
   投入：中｜收益：差异化，但优先级低于播放稳定性。

### 不建议现在做

- 做通用资讯聚合/爬虫站：内容合规和版权成本高，现有“公开来源 + 整理”边界更稳。
- 做社交关系链/评论社区：人力审核成本高，见闻的定位更适合“个人阅读工具”。
- 做付费墙：用户规模还不够，先把这个工具做到每天愿意打开。

## 二、拙政观景（jianwen.xin/zhuozheng/）

### 现在能做什么

| 模块 | 能力 |
|---|---|
| 手法 | 借景、框景、对景、障景、漏景、夹景等造景手法的图文讲解 |
| 地图 | 园内点位与手法对应，可点选查看 |
| 案例 | 具体景点/场景的手法拆解 |
| 探索 | 按主题/手法浏览内容 |
| 工坊 | 用户生成/编辑自己的造景方案（studio） |
| 社区 | 用户作品发布、浏览、详情 |
| 阿烬 | 园林与造景相关问答 |
| 账号 | 登录、我的作品/记录/收藏 |

### 建议（按优先级）

**P0｜把“学手法”变成“能对照”（3–4 周）**

1. **同场景多手法对照**
   选一个真实场景（如“与谁同坐轩”），并排展示“借景/框景/对景”各自怎么用、画面差在哪；这是现有内容最缺的一层。
   投入：小（内容为主）｜收益：直接提升“看懂”的比例。

2. **照片判手法（图像识别）**
   上传自己在园里拍的照片，模型给出“可能用了哪些手法 + 依据 + 相似案例”。这是拙政相对见闻最容易做出差异化的点。
   投入：大｜收益：传播点强，但需要标注数据和模型成本。

**P1｜从“看”到“走”（1–2 个月）**

3. **园内游览路线**
   按“1 小时精华 / 半日深度 / 摄影机位”给三条路线，每站一句话讲手法，支持离线打开。
   投入：中｜收益：真实到园用户会用，和地图天然结合。

4. **作品标注地图**
   用户上传照片时可标点位与手法，审核后进入“社区案例地图”；比纯作品流更有结构。
   投入：中｜收益：UGC 质量与复用。

5. **每月主题挑战**
   如“春季借景”“窗框里的拙政”，一月一题，优秀作品进首页；比长期开放投稿更容易运营。
   投入：小｜收益：内容更新节奏。

**P2｜技术增强（季度）**

6. **AR 预览**
   摄像头对着实景叠加“如果换成框景/漏景会怎样”的示意；演示价值大于实用价值。
   投入：大｜收益：传播，但别作为近期目标。

7. **诗句/文献层**
   每个手法配 1–2 句古典诗文与出处，可切换“看景/读文”两种讲解。
   投入：小｜收益：文化厚度，和见闻的经典文献可互相导流。

8. **课程/工作坊**
   与园林机构合作线上课或线下工作坊，站内报名；先做 1 期验证，不急着做课程平台。
   投入：中｜收益：可能的收入来源。

### 不建议现在做

- 做 3D 全园建模/VR 漫游：成本高、更新难，现有实拍 + 地图已够用。
- 做重社交（关注/私信/排行榜）：没有足够用户前，社区会变成空城。
- 做门票/导览交易：涉及资质与售后，个人项目不划算。

## 三、两个项目怎么互相借力

1. **账号打通**：同一个手机号登录两个站，收藏/作品/阅读记录互通；技术上共用一套 auth 即可。
2. **内容互链**：见闻的经典文献（如《园冶》相关）→ 拙政的手法页；拙政的案例 → 见闻的“专题”。
3. **朗读复用**：见闻的 TTS 管线可以直接给拙政的讲解页做“听讲解”，成本很低。
4. **视觉统一**：本轮已把“经典文献”卡片在 App 和网站统一为“封面 + 标题 + 作者/来源”，去掉长简介；两个站可以继续共用这套卡片语言。
5. **运营复用**：一次拍摄/一篇长文，拆成见闻文章 + 拙政案例 + 小红书图文，别做两套内容。

## 四、接下来两周的建议顺序

1. 见闻 1.1.11 整包：前台服务保活 + 断点续播（解决“锁屏会停”）
2. 见闻每日五篇完成态 + 连续天数（低成本留存）
3. 拙政“同场景多手法对照”第一版（内容为主，先做 3 个场景）
4. 阿烬引用原文（见闻）与拙政问答共用同一套引用组件
